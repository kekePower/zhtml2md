# Character-reference component fixtures

Each case has literal input (`.input`), exact decoded bytes (`.decoded`),
status (`.status`), original-input byte offset (`.offset`), and exact
diagnostics (`.stderr`). These are decoder fixtures, before Markdown
escaping or whitespace normalization. CR remains CR at this boundary.
The decoder is tested directly; these files do not yet describe public
conversion output.

`zsh -df tests/gen-entity-fixtures.zsh` regenerates the 20 hand-authored
cases. Review changes to expected bytes against the implementation
contract, not against converter output.

`all-named` covers every one of the 2,125 semicolon-terminated names in
the WHATWG data recorded in `data/README.md`, in sorted order with an LF
after each entry. Expected bytes were independently encoded with Python
`chr(int(hex, 16)).encode('utf-8')` from the recorded scalar fields;
they were never generated by the Zsh decoder. This oracle is retained
separately from the hand-authored generator and only changes when the
vendored data changes deliberately. Running the tests needs no Python.

`tests/integration/entities.zsh` runs these cases and covers all forbidden
C0/DEL references, long numeric candidates, capture boundaries, lazy
cache loading, malformed/missing data, retry after failure, descriptor
cleanup, caller regex state, adverse options/aliases, and empty-PATH
runtime operation.
